# راه‌اندازی ربات سبزنت روی Railway

## فایل‌های پروژه
- `SabzNet_admin.py`: سورس اصلاح‌شده
- `requirements.txt`: وابستگی پایتون
- `Procfile`: دستور اجرای Worker
- `.env.example`: نام متغیرهای محیطی موردنیاز

## قبل از آپلود در GitHub
1. توکن قبلی که داخل فایل اولیه قرار داشت افشا شده است. در BotFather آن را باطل (Revoke) و یک توکن جدید تولید کن.
2. توکن جدید، شماره کارت، نام صاحب کارت و لینک اشتراک را داخل کد یا GitHub قرار نده؛ فقط در Variables سرویس Railway ذخیره کن.
3. فایل `.env`، دیتابیس و اطلاعات محرمانه را در GitHub آپلود نکن.

## متغیرهای Railway
در سرویس Railway از بخش Variables این مقادیر را بساز:
- `BOT_TOKEN`: توکن جدید ربات
- `ADMIN_IDS`: آیدی عددی ادمین‌ها، با کاما جدا شوند. آیدی مدیر اصلی در نسخه آماده‌شده `9158813748` است؛ در صورت نیاز می‌توان آن را در Railway تغییر داد.
- `OWNER_CHAT_ID`: آیدی عددی مالک برای دریافت رسیدها
- `DATABASE_PATH`: مقدار `/data/sales.db`
- `CONFIG_IMAGE_PATH`: مقدار `photo_5771850719550967090_y.jpg` (اختیاری)
- `PAYMENT_CARD_NUMBER`: شماره کارت دریافت وجه
- `PAYMENT_CARD_OWNER`: نام صاحب کارت
- `CONFIG_SUBSCRIPTION_LINK`: لینک اشتراک کانفیگ (محرمانه نگه دار)

## دیتابیس دائمی (مهم)
SQLite در فضای موقت Railway ممکن است با ری‌دیپلوی یا راه‌اندازی مجدد پاک شود. از سرویس یک Volume بساز و آن را روی مسیر `/data` متصل کن. سپس `DATABASE_PATH=/data/sales.db` باشد.

## اتصال به Railway
1. این پوشه را در یک مخزن GitHub آپلود کن.
2. در Railway یک پروژه جدید بساز و گزینه Deploy from GitHub Repo را انتخاب کن.
3. مخزن را انتخاب کن و Variables بالا را تنظیم کن.
4. یک Volume با Mount Path برابر `/data` اضافه کن.
5. سرویس را به‌صورت Worker اجرا کن؛ Procfile دستور اجرا را مشخص کرده است.
6. فقط یک نمونه از این ربات را هم‌زمان اجرا کن، چون از long polling استفاده می‌کند.

## نکات
- `ADMIN_IDS` باید شامل آیدی عددی حساب‌هایی باشد که اجازه مدیریت و تأیید رسید دارند.
- `OWNER_CHAT_ID` اختیاری است؛ اگر خالی باشد، ارسال خودکار رسید به مالک غیرفعال می‌شود.
- فایل عکس کانفیگ اختیاری است؛ در نبود آن ربات متن کانفیگ را ارسال می‌کند.
- دیتابیس موجود در اجرای قبلی به‌صورت خودکار منتقل نمی‌شود؛ اگر سابقه‌ها مهم‌اند باید جداگانه منتقل شوند.

## امکانات تکمیلی پنل مدیریت

با دستور `/admin` پنل مدیریت باز می‌شود. امکانات اضافه‌شده:

- پیام همگانی با کپی متن، عکس، ویدئو، فایل، استیکر و سایر پیام‌های پشتیبانی‌شده تلگرام
- بکاپ SQLite با دانلود فایل دیتابیس
- ریستور بکاپ معتبر SQLite و راه‌اندازی مجدد خودکار فرایند
- ساخت کد تخفیف درصدی با محدودیت تعداد استفاده، فعال/غیرفعال کردن کد و اعمال با دستور `/coupon CODE`
- افزودن دسته‌بندی با شناسه انگلیسی و عنوان دلخواه، فعال/غیرفعال‌سازی دسته‌بندی
- افزودن محصول به دسته‌بندی، تغییر نام، آیکون، استیکر، قیمت، موجودی و حذف/فعال‌سازی محصول
- کسر یک واحد از موجودی محصول پس از تأیید پرداخت؛ مقدار `-1` به معنی موجودی نامحدود و `0` به معنی ناموجود است
- فهرست کاربران به‌صورت صفحه‌بندی‌شده
- ویرایش متن‌های اصلی از پنل «ویرایش پیام‌ها» (خوش‌آمدگویی، پشتیبانی، راهنما، تست، متن تحویل کانفیگ و پیام‌های تأیید/رد پرداخت)

نکته: برای بکاپ پایدار روی Railway حتماً Volume را روی `/data` متصل و `DATABASE_PATH=/data/sales.db` تنظیم کنید. بکاپ ریستور باید فایل دیتابیس همین ربات باشد؛ پس از ریستور، پردازش ربات به‌صورت خودکار Restart می‌شود.

## اصلاحات و بررسی نسخه فعلی
- موجودی هنگام تأیید فاکتور در تراکنش اتمیک بررسی و کسر می‌شود؛ اگر موجودی صفر شده باشد، فاکتور تأیید نمی‌شود.
- دسته‌بندی‌های سفارشی پس از تأیید پرداخت به‌اشتباه لینک کانفیگ دریافت نمی‌کنند و به پشتیبانی ارجاع داده می‌شوند.
- متن تحویل کانفیگ حتی در حالتی که تصویر کانفیگ فعال باشد، از متن ذخیره‌شده در پنل خوانده می‌شود.
- فایل ریستور علاوه بر بررسی جدول‌های ضروری، با `PRAGMA integrity_check` از نظر سلامت SQLite بررسی می‌شود.
- ورودی شناسه دسته‌بندی و کد تخفیف اعتبارسنجی می‌شود و ویرایش متن فقط پیام متنی می‌پذیرد.

بررسی فنی انجام‌شده: کامپایل پایتون، تجزیه AST، اجرای آزمایشی بارگذاری برنامه با ماژول تلگرام شبیه‌سازی‌شده، مهاجرت دیتابیس قدیمی و بررسی ساختار/داده اولیه انجام شده است. با این حال، تأیید نهایی ارتباط واقعی با Telegram و اجرای تمام دکمه‌ها فقط پس از قرار دادن توکن و اجرای آزمایشی روی Railway ممکن است.
